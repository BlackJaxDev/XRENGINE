## Current State

The publisher now prepares the unchanged-row verdict during collection and checks its witnesses during the serial swap. The commit stays in the swap. The primary directional shadow view collects only when a consumer needs it. The latest desktop comparison at 2,000 chains averages 44.61 Hz with preparation enabled and 41.62 Hz with it disabled; the mean swap falls from 7.30 ms to 5.41 ms. The live-edit check of the prepared verdict is still open. The transform store now notifies only rows with handlers or overridden change methods: in interleaved windows on 2026-10-15 the swap fell by about 0.4 ms and the update-thread `Process` hold by about 0.8 ms, with no measurable frame-rate change. A swap that does not wait for `Process` was rejected, because it made the Advanced commit slower in half of the sessions. See the [swap transform publication](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#swap-transform-publication) results. The dispatcher now reuses unchanged bounds rows; the rows stage fell from about 3.3 ms to about 0.9 ms per frame, and 2,000-chain captures with reuse on and off contain all current and previous positions. See [retained bounds rows](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#retained-bounds-rows). The commit now notifies only renderers whose committed bound changed and advances the covered shadow revision once for each scene; the commit fell from 0.75–1.00 ms to under 0.01 ms. The simulation group no longer keeps layout checks or upload stamps and caches the kernel buckets; it fell by about 0.2 ms. The dispatcher now takes 5.55–5.70 ms per frame, and the windows ran at 43.0–43.6 Hz. See [commit notifications and simulation group](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#commit-notifications-and-simulation-group). Renderers now read the chain palettes through one shared palette view, so the palette source stage fell from about 0.65 ms to 0 ms; the previous palette uses one range copy for an unchanged layout and fell by about 0.1 ms. The dispatcher took 5.10–5.49 ms per frame in normal windows. See [previous palette and palette sources](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#previous-palette-and-palette-sources). The 100 Hz target remains open.

## Priority Order

Steady-state target: an unchanged, fully covered GPU chain and its renderer cause no per-frame CPU work, except the bulk root write and a fixed number of dispatches and draw commands for each bucket. See the [design rules](../../design/physics/physics-chain-steady-state-cpu-design.md#design-rules).

Make decisions from the cost per chain of each frame phase, not from the frame rate alone, and measure each change in both mesh modes.

Work in this order (agreed 2026-10-13, after the stage telemetry). The frame interval is the longer of render until it releases the collect thread and collect, plus the serial swap:

1. Remove the swap transform-store wait ([Serial swap](#serial-swap)), about 0.3–0.7 ms. The owner notification filter is done.
2. The other [structural frame reuse](#structural-frame-reuse) and [render-thread](#remaining-render-thread-items) items, by measured cost. The retained bounds rows, the commit notification filter, the simulation-group changes, the previous palette copy, and the shared palette view are done.
3. Other [collection](#collection) items, when render falls below collect.
4. [Physics inputs at the render rate](#physics-inputs-at-the-render-rate).

The GPU floor is measured: with locked clocks, the GPU takes about 3.7 ms fixed plus about 1.6 µs per chain, 7.0 ms at 2,000 chains (see the [investigation](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#gpu-floor-with-locked-clocks)). The critical path must therefore fall from about 13.6 µs to about 2 µs per chain.

Physics rate requirement (2026-10-13): physics inputs should also run at 100 Hz. When the physics rate is lower, the GPU presents interpolated or extrapolated chain poses at the render rate, as in the [distance cadence design](../../design/physics/distance-cadence-gpu-presentation.md). The update thread does not set the frame interval, so its items come after the render, swap, and collect items, but they still matter: they set input latency and use CPU power that a laptop shares with the GPU.

Keep runtime checks and performance acceptance in the [validation plan](../../testing/physics/physics-validation.md#bottleneck-measurements).

## Open Code Items

### Structural frame reuse

When the scene structure has not changed since the last frame, each consumer reuses its prepared per-row state and updates only per-frame GPU data (pose, bounds, palettes, history, and output-page leases). Each consumer needs a complete change witness: a change it does not see would draw stale state. Build the shared versioning contract with the first consumer that needs page versions.

- [ ] Add one shared page-version type for dense row stores. Put it in a shared low-level project so that Core and Rendering can both use it. Each page of rows has a local 64-bit version that increases only on a real write to a row in that page. A reader keeps its last-read version for each page and skips unchanged pages. Done when: unit tests cover a write, an unchanged read, scattered and clustered changes, page growth, row removal, and a reader that misses several writes; and a "no changes" read of 2,000 rows makes one comparison for each page.
- [ ] Give `TransformHierarchyStore` page-local sequences and a range read. Today one `_sequence` covers the whole store, each write takes `_gate`, and each read uses a full memory barrier. A write to any transform therefore makes concurrent readers of every transform retry. Done when: a write to one page does not make readers of another page retry; a range read copies many matrices under one sequence check; and unit tests cover a concurrent writer during a range read, a stale handle, and growth.
- [ ] Let an unchanged publication skip the per-row gate walk in `AdvancedGpuScenePublisher.UnchangedRowGate`. The gate already skips the whole-scene plan and commits retained rows, but it still visits every row in each publication (scene command and source lookups, a render-snapshot copy, and the registration checks). Use page versions for the command rows and their row inputs. Done when: an unchanged publication visits no unchanged row; every input that the gate reads today has a page-version witness; and the gate contract tests in `AdvancedGpuSceneUnchangedRowGateTests` pass with page-level dirty cases.
- [ ] Separate stable Advanced preparation templates from frame bindings. `AdvancedPreparationExtractor`, `AdvancedSharedPreparationService`, `AdvancedGpuDeformationResources`, `VulkanAdvancedVisibilityInputStorage`, and `VulkanPreparedStableBinStream`. Done when: unchanged mesh, material, topology, and group revisions reuse immutable preparation templates across render frames, and steady-state extraction visits only changed rows; current pose, bounds, root motion, interpolation, previous-render history, frame-specific resources, and output-page leases remain fresh; and an unsupported or changed source takes the existing strict preparation path. A held physics output page alone must not authorize reuse of a complete frame request or displayed deformation.
- [ ] Retain the visibility input variant across frames (estimated 0.3 ms). `AdvancedVisibilityInputVariant`, `AdvancedIndexedInstanceGroupPlanner`, and `AdvancedIndirectRangePlanner`. Done when: equal frames copy the retained ranges, producers, and groups, and a change to one payload's geometry, material, or count rebuilds them.
- [ ] Replace the per-request loops in `GPUPhysicsChainDispatcher.ProcessDispatchesCore` with page-versioned request rows. In each render frame, the dispatcher calls `TryAcceptInput` and `PhysicsChainComponent.AcceptGpuDrivenBoneBindings` for every active request, and `RefreshGpuDrivenBoneBindings` for every registered component, under the registration locks. ### Serial swap

`EngineTimer` runs the swap after collection finishes and the render thread releases the collect thread (just after queue submit on Vulkan). The render thread cannot start the next frame during the swap. At 2,000 chains on the desktop, the prepared unchanged-row verdict reduced the mean swap from 7.30 ms to 5.41 ms on 2026-10-14. The remaining items below retain their earlier measurements.

- [ ] Do not block the serial swap on update-thread transform propagation (measured 0.32–0.43 ms per frame after the notification filter, 0.72–0.76 ms before). `TransformHierarchyStore.PublishRenderMatrices`. A swap that skipped its publication when `_passGate` was busy made the Advanced commit in the swap 7.4–8.9 ms instead of about 3 ms in 3 of 6 sessions, with more data copied in `AdvancedSharedGpuSceneDatabase.TrySealTablePublication`; see the [investigation](../../investigations/physics/skinned-gpu-chain-benchmark-2026-10-06.md#swap-transform-publication). Find that cause first. Done when: the swap no longer waits for `Process`, a unit test shows that a skipped publication publishes at the next call, and interleaved windows show no Advanced commit increase in either mesh mode.

### Collection

Collection (about 8 ms on the desktop since the primary shadow gate) is not on the critical path: render takes 17–18 ms until it releases the collect thread, and collect finished later in no frame of the 2026-10-14 windows. A collect saving shortens the frame only when render falls below collect, or when it makes room to move swap work into collect. Savings are estimates from the 2026-10-12 mapping unless marked as measured.

- [ ] Remove `Thread.Sleep(1)` from `TransformHierarchyStore.Read` retries and shorten the publication write window (estimated 1 ms, mainly p95). Use `SpinOnce(sleep1Threshold: -1)` at both retry sites, and bracket each 64-row chunk of `PublishRenderMatrices` with its own write sequence. Done when: read-contention telemetry shows a maximum spin count below 20 and lower retry time, and unit tests show untorn reads under a concurrent writer and during growth.
- [ ] Use the reconcile result and skip bound queries in render-matrix handlers of covered meshes (estimated 1–2 ms of collect and swap before the query cache; less now). `RenderableMesh.ReconcileCommittedWorldBounds` returns the coverage it computed; `RootBone_WorldMatrixChanged`, `Component_WorldMatrixChanged`, and the render-matrix update paths use a reconciled-coverage flag, and coverage loss queues one render-matrix update. Done when: a covered mesh makes one bound query per collection and none per root notification, and coverage loss still restores CPU culling bounds from the current root matrix.
- [ ] Remove small per-mesh collection costs (estimated 0.3–0.6 ms each). Return early from `RenderInfo3D.Intersects` for a null culling volume; reuse the collected sort bound in `RenderCommandMesh3D.AddCPU`; skip camera-distance reads in `RenderableMesh.BeforeAdd` for shadow passes; remove the second full `CanUseCanonicalGpuCollection` per mesh in the main view; merge the two per-frame skinned-mesh passes in `VisualScene3D.GlobalCollectVisible`. Done when: each change has the unit test named in its mapping entry, and collection results are unchanged.
- [ ] Batch transform propagation per range (estimated 0.3 ms; measure sequential and pooled propagation first). `TransformHierarchyStore.Process` with one `_gate` hold and one sequence pair per range of plain transforms. Done when: range propagation equals per-transform propagation for random hierarchies, and a concurrent write during `Process` is safe.
- [ ] Give the primary directional shadow tile an explicit native GPU consumer and command ownership contract. `DirectionalLightComponent.CascadeShadows`, `ShadowRenderPipeline`, `RenderCommandCollection`, and GPU shadow culling. `VisualScene3D.CanCollectCoveredSourcesOnGpu` excludes shadow passes, so each covered mesh now runs `BeforeAdd` and `AddCPU`, with a lock and a sorted insert, for the primary shadow view. This is the second `CollectRenderedItemsGpu` call in each cycle. Done when: eligible primary tiles avoid CPU mesh collection while retaining CastShadow, layer, mirror, and non-mesh policy, and rejected strict work remains dirty without an empty or CPU fallback draw. ## Decisions Needed

- Set additional named-hardware physics budgets and scaling targets. The current requirement is at least 100 completed rendered frames per second with 2,000 visible animated chains and frame-interval p95 at most 10 ms, in both the shared-mesh and unique-mesh scenarios. Keep acceptance in the [validation plan](../../testing/physics/physics-validation.md). Owner: physics runtime.
- Choose the page size for each row store and the enlargement margin for covered spatial proxies. In the microbenchmark, 1% scattered changes in 64-row pages cost 61–65% of a full dense rewrite. Rows that change together should share pages. Owner: physics runtime and rendering.
- Decide whether shared-mesh chains also need a world-owned batch source, with one scene registration for each mesh and material set. Decide after the change-driven renderer path is measured in the shared-mesh scenario. Owner: rendering.
- Select the presentation latency and history policy. The user permits a lower simulation cadence for distance tiers and for the whole physics rate, with rendered interpolation or extrapolation up to the render rate (2026-10-13). Interpolation adds one physics step of latency; extrapolation has no added latency but can overshoot. Keep full-rate measurements as the reference and report the exact distance profile for quality-tiered acceptance. Owner: physics runtime.
- Name the cross-vendor GPU and lower-tier CPU and GPU targets. Owner: physics runtime.
- Approve any serialized data change before implementation. Use a separate migration plan. Owner: maintainer.
- Decide whether a temporary old-versus-new runtime selector is necessary for comparison. Owner: physics runtime.

- An angular joint representation for linear chains.
- A segment-major wave GPU kernel.
- Reciprocal square root or reduced-precision GPU math.
- Kernel autotuning by vendor, segment bucket, collider class, and active count.
- 16-bit storage for indices, rest data, coefficients, or state.
- Quaternion or dual-quaternion palette output.
- Shared-memory collider staging.
- Persistent GPU work queues or cooperative kernels.
- General cross-family Vulkan asynchronous scheduling and automatic async-physics promotion. The bounded same-family experiment is listed above.
- GPU-only broadphase. GPU activity, tier assignment, and sleep compaction remain backlog items.
- Core-class-aware scheduling and NUMA partitioning.

Not planned: replacing the rigid-body solver or character controller, a broad ECS rewrite, silent quality reduction, silent CPU fallback, current-frame full-state readback, bit-identical CPU and GPU trajectories, and permanent support for two runtime architectures.
