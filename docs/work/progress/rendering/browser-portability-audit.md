# Browser portable dependency and API audit

The selected browser profile is the untrimmed .NET 10 WebAssembly interpreter with an explicit WebGPU composition root. The browser project references Core, Rendering, and WebGPU; Core references Data and Extensions; Rendering references Data, which references Extensions. Audio is excluded. A neutral target framework alone is not evidence of browser portability.

The source-declaration report and the evaluated report serve different purposes. Run the existing declared union with `python Tools/Reports/audit_browser_dependencies.py --output <report-path>`. After restoring the browser graph, use `python Tools/Reports/audit_browser_dependencies.py --mode evaluated --configuration Release --output <report-path>`. The latter asks MSBuild for each project's evaluated project/package/compile/content/reference items, follows project references, records imported build files, and reads every reachable `project.assets.json` target for transitive package versions, dependencies, build imports, native/runtime assets and source initializer/reflection candidates. It fails if a referenced project, Compile item, or restore target is absent. The report is generated evidence, not a checked-in snapshot or a claim that restore and evaluation were run here.

The compile-source guard is `Build/Portable/PortableSourceApiGuard.cs`, compiled and hosted by the SDK's `RoslynCodeTaskFactory`. MSBuild passes evaluated Compile items directly; no external interpreter, source-list file or extra package is required. `Build/Portable/SourceApiPolicy.tsv` is the common policy for this task and the optional dependency report tool. The Python report tool is not invoked by builds.

| Dependency | Disposition | Owner and boundary |
|---|---|---|
| Browser, Runtime.Core, Runtime.Rendering, Runtime.Rendering.WebGPU | Portable selected source closure | Browser/runtime/rendering maintainers; explicit portable items and composition |
| Data | Portable selected managed subset; full desktop tree excluded | Data maintainer; `Build/Portable/Data.items` limits source and MemoryPack/YamlDotNet packages |
| Extensions | Portable selected managed subset; full desktop tree excluded | Data maintainer; `Build/Portable/Extensions.items`; no desktop Meshoptimizer package |
| MemoryPack, YamlDotNet | Managed serialization references; restored transitives require individual review | Data serialization maintainer; evaluated report lists exact resolved versions and assets |
| Audio, native codec/OpenAL/FFmpeg/CUDA/NAudio implementations | Desktop-only and excluded from this browser milestone | Audio maintainer; no browser reference or runtime registration |
| Desktop window, XR, DirectStorage, native font/image/physics, Rive, NVIDIA and native submodules | Desktop-only or offline-cook-only; excluded from runtime | Corresponding desktop/runtime/asset owner; portable project declarations and native copy guards reject them |
| WebGPU JavaScript and cooked shader assets | Browser replacement/offline-cook output | WebGPU and shader cooking owners; not native library dependencies |

The portable target now rejects Windows TFMs, unreviewed project/package references, native copy items, and trim/AOT publish flags. Immediately before compilation it scans **evaluated Compile items**, including Data and Extensions, with a source guard. It rejects interop, known desktop/native namespaces, dynamic code/assembly loading, and process/registry desktop services. Reflection candidates outside narrow reviewed file/symbol entries fail the guard. Reviewed entries are managed type discovery, event-method resolution, and reflection helpers that are present in the untrimmed interpreter; this does not establish trim/AOT compatibility. The report also flags module/static initialization candidates for owner inspection.

The selected source list was inspected at the pinned source revision. `XRWorldObjectBase` has a static constructor that initializes replication metadata and may scan loaded assemblies; `XRComponent` constructs components through an uninitialized object and reflected constructor; `XRBase` specializes a MemoryPack clone helper by reflected generic method. Data's persisted type resolver and event calls, Extensions' helper methods, transform/component attributes, and renderer module framework metadata also use managed reflection. The guard's file/symbol entries identify precisely these interpreter allowances and reject new call sites. Browser composition does not register desktop Audio or Bootstrap services; that assertion still requires actual browser execution to verify implicit initialization.

This lexical guard masks comments and literals but does not resolve aliases, indirect calls, code inside interpolated expressions, generated code after the Compile snapshot, or method dispatch. MSBuild evaluation and NuGet assets are not a runtime reachability proof or publish manifest. A browser publish and runtime exercise must verify initialization order, serializer round trips, WebGPU startup and assets; trim/AOT need separate registration and metadata preservation review before either flag may be enabled. The evaluated report must be inspected for every `transitive review required` package and native asset before claiming the dependency audit closed. No build, report execution, or browser validation was run for this change.
