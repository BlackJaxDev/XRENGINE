# Browser UI image profile

The shared screen UI collector now has a cooked WebGPU image-quad profile alongside solid-color quads and bitmap text. A single image batch groups painter-adjacent quads by texture identity and clip region. It retains the existing 64-byte matrix, tint, and bounds instance streams, adds one `float4` UV rectangle per image, and binds the group's image and filtering sampler as `Texture0`. The profile is `UIQuadBatchedTexture` version 1, `screen-ui` / `instanced-ui-quad-texture-v1` / `display-rgba-v1`. The Slang raster source is `WebGPU/UIQuadBatchedTexture.slang`.

`UIMaterialComponent.CreateImageMaterial` creates a canonical tinted desktop fragment material and an explicit cooked construction-target companion. Browser publication accepts only this exact engine stage or its source-free companion, one single-sample display-space RGBA8 image with the declared `Texture0` sampler, one `MatColor` parameter, and the existing straight-alpha screen raster state. This first image profile keeps RGBA8 texels in display space; sRGB-decoded and HDR samples need a separately specified output encoding. Custom fragment stages, other formats, and incompatible sampler or mip data fail with a UI-specific diagnostic. Existing desktop materials and GLSL draw paths remain unchanged. The texture cache borrows image resources, retires superseded per-texture renderers on a cache miss, and caps concurrent visible image resources at 64.

Per-glyph rotation is not represented by the batched text ABI: `GlyphTransformsBuffer` stores only `(minimum x, minimum y, width, height)`; desktop rotatable text uses a separate rotation buffer and rotates around the text-local origin. This profile does not substitute axis-aligned text for rotated glyphs. MSDF/MTSDF atlas shading remains outside the bitmap text profile.

Validation: pinned Slang 2026.8 compiled the source to WGSL; the isolated ShaderCooker packaged the exact recipe (one artifact). The isolated WebGPU, BrowserContentCooker, and Editor projects built with zero warnings or errors. JavaScript syntax and recipe JSON validation passed. The browser known-value image render belongs to the next coherent end-to-end UI milestone and remains to be recorded.

The later offscreen UI cook uses version 2 of all three batched screen UI semantics with the exact `canvas-rgba-v2` output profile. It also publishes `UICanvasSurface` version 1 as `canvas-composite` / `position-uv-v1` / `linear-hdr-premultiplied-rgba-v1`. Browser asset-catalog validation now admits those precise pairs while retaining the version 1 `display-rgba-v1` pairs, strict seven-member variant records, descriptor identities, and malformed or unknown profile rejection. The same catalog alignment admits the cooker's exact `UberOutline` version 1 profile. A Node probe invoking the production validator against eight hash-verified cooked descriptor variants passed, including all three UI variants in both versions, the canvas surface, and an outline variant; 15 malformed, version, profile, target, identity, and duplicate-key cases were rejected. This checks manifest admission, not rendered pixels.
