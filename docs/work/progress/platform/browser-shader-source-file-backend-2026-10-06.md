# Shader source refresh file backend

Shader source hot reload now uses an optional host file backend for its physical file operations. Rendering keeps change ownership, debounce, retry timing, source capture, and frame-swap publication. The desktop platform installs the file backend during normal Editor and headless startup. The backend checks file existence and length with `FileInfo`, opens a read handle with `FileShare.ReadWrite | FileShare.Delete`, and reads root text with the retained encoding and cancellation token. The existing six stability attempts and 40 ms delay remain in Rendering.

Each queued change and manual reload captures one file backend and its installation generation. Work checks for a replaced backend before file access, after awaited work, and before publication. Reinstalling the same backend also retires old work. A file operation admitted before replacement can finish, but its result is rejected before publication. An admitted synchronous notification can finish if the backend changes after its final admission check. This follows the existing shader source-owner admission rule.

A host that permits desktop shader source work but does not install the backend receives `ShaderSourceRefresh.HostFileBackendUnavailable` through the shader service warning channel, or the engine warning channel when no shader service is installed. A queued change is not started, and a manual reload returns zero. Custom and pre-bootstrap desktop compositions must install a file backend before they request disk refresh. They can set `ShaderSourceFileBackendServices.Current = new DesktopShaderSourceFileBackend()` without registering window or input services. Browser hosts do not install one. The standalone browser publisher uses its own authored-file adapter for cooking and is unchanged. Direct include and snippet resolution is unchanged.

This move addresses only the physical file probes and root reads in shader source refresh. Other runtime file calls and the wider UR03.02b inventory remain open. The change adds no format, dependency, or test. Independent source and lifetime review passed. The combined Rendering/Desktop Release build passed with zero warnings and errors. No browser or live Editor hot-reload result is claimed here.
