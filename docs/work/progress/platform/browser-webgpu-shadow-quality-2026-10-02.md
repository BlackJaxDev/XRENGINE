# Browser WebGPU shadow quality

The shared engine's browser output applies its selected shadow limits when an active light creates a shadow target. The light's authored dimensions remain unchanged. The output target and its shadow viewport use the same aspect-preserving effective dimensions, bounded by `MaxDirectionalShadowDimension`, `MaxPointShadowDimension`, or `MaxSpotShadowDimension`. Point maps remain square. Directional texel-scale bias uses the effective dimensions. Desktop GLSL allocation and shadow rendering do not use these limits.

The high, balanced, and low browser profiles render unchanged standalone shadow maps at intervals of 1, 2, and 3 render frames respectively. The selected interval is validated in the range 1–120. Collection and shadow rendering remain on the shared world path; there is no second browser-only shadow scene.

Reuse is allowed only for unchanged static opaque color casters or an unchanged empty caster set. Skinned, blendshape-capable, mesh-deformed, multi-instance, textured, coverage, and unrecognized caster commands refresh every frame because their silhouette can change without a reliable revision in the shared command signature. A published per-command render-options override also forces refresh. For reusable casters, the browser cache tracks each resolved mesh and material object identity, mesh geometry revision, material value/resource/shader revisions, mode, semantic, and source-material cull/winding/depth state in addition to the published command signature. Reuse still requires the same light-owned framebuffer and receiver, renderer and output generation, light binding, caster membership, producer projection, and authored dimensions. A selected reuse authorizes only that light and receiver for the current frame. Capture requests that collect visible casters immediately bypass cadence.

Framebuffer writes carry a per-texture monotonic production ticket, separate from sampled-read hazard tracking. A ticket becomes reusable only when that exact producer frame is accepted. An aborted frame, unrendered viewport, recreated storage, renderer replacement, or later capture cannot make stale cached contents appear current. The receiver declines an unproduced or unauthorized image instead of presenting it with a newer producer matrix. Destroying or replacing a light's shadow target clears its cached ownership.

Validation: the Release `XREngine.Runtime.Rendering.WebGPU` project graph built with zero warnings and zero errors in the existing `ui-shaders/temp-build` artifacts root. The static shadow-reuse review found no remaining blocking lifetime, ownership, matrix, sizing, or allocation issue after the producer-ticket and cook-admission repairs. Browser-device runtime cadence and visual quality have not yet been exercised; no WebGPU image comparison or performance measurement is claimed here.
