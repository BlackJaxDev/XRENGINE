# Browser WebGPU asynchronous readback

The WebGPU engine renderer accepts canvas screenshots and pixels as bounded asynchronous requests. Each request captures the next complete engine frame on the same canvas generation, after the frame's GPU submission and before implicit browser presentation. Every engine frame opens bounded validation and out-of-memory scopes; a pending capture shares that frame receipt and adds its own copy scopes, so completion is gated on both the producing frame and the copy; a validation-failed or incomplete frame cannot supply a successful image. A captured producer validation error still fails the renderer. Frames without a pending capture use the same validation scopes without allocating a capture gate. Hiding the page cancels pending canvas requests; a visible canvas that stops submitting frames fails pending requests after five seconds. Resize, renderer teardown, device loss, cancellation, and stale session/surface generations fail the request rather than returning an older frame. The browser permits at most 16 live GPU tickets, 16 MiB of returned bytes per request, and 32 MiB of ticket-owned returned plus staging memory.

Engine `BoundingRectangle` and pixel points are bottom-left coordinates. WebGPU copy origins and `RuntimeImage` rows are top-left. Canvas BGRA bytes are reordered to RGBA before delivery, and `withTransparency == false` forces opaque alpha. The canvas currently uses opaque presentation, so requesting transparency cannot recover translucency that was already discarded by canvas composition. Pixels are presentation-space bytes; readback does not linearize sRGB. The `RuntimeImage` owner is transferred once to a successful screenshot callback. Task-based `CaptureCanvasAsync` and `ReadCanvasPixelAsync` accept cancellation tokens and surface exceptions directly. The legacy callbacks report failures through a null screenshot or transparent pixel plus a renderer warning. Structured screenshot callbacks carry a failure result.

`ReadEngineDepthAsync` reads a committed, single-sample `depth32float` 2D framebuffer attachment through the same asynchronous texture ticket path. WebGPU requires a whole-depth-mip copy, so it copies a bounded complete mip and selects the requested pixel from the mapped bytes. Mips larger than the readback budget reject explicitly. It also rejects reads during C# frame recording because copying immediately would sample the previous submission. Depth16, depth24plus, combined depth/stencil, array layers, and synchronous depth reads remain unsupported. The callback adapter reports asynchronous failure with a warning and depth 1; the task API retains the exception.

Luminance reduction is a separate GPU feature described in [the luminance behavior note](browser-webgpu-luminance-2026-10-02.md). The explicitly compute-requested front entry point runs a GPU reduction; unsupported texture-mip and sRGB legacy cases reject explicitly rather than silently using a CPU reduction.
