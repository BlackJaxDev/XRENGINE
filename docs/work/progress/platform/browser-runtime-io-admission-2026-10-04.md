# Browser runtime I/O admission

The runtime I/O sites classified below now admit their actual host capability before a file probe or output creation. This is source and narrow managed validation; it does not establish Browser page startup or rendered pixels. The source inventory classified candidates before this implementation; lexical reachability alone did not qualify a call path.

## Asset response ownership

`Engine.Networking` binds the receiving network manager when it subscribes to remote requests, then captures the `AssetManager` and local peer ID at request entry. The pushed-payload transfer remains a direct response. Requested bytes pass through `AssetManager.ServeRemoteAssetAsync`: it captures that manager's source, epoch and cancellation lifetime; checks catalog membership through the captured catalog; and reads through the captured source. A missing noncatalog asynchronous source path is determined by the read's `FileNotFoundException`, without a synchronous existence probe. Desktop file and metadata-ID lookup retain their admitted host route. Metadata resolution reserves the owner while it runs, and response construction holds the existing finite remote-publication reservation after the await. Retirement cancels the pending catalog read or rejects stale completion. Response path metadata and payload bytes retain their former wire shape; the sender ID comes from the bound network session instead of a later global lookup.

The sole in-repository `RemoteJobRequestReceived` subscription is `Engine.InitializeNetworking`. Browser's `ConnectWebSocketClientAsync` starts a WebSocket client but does not subscribe this remote-job handler. The catalog-owner probe qualifies the handler if used with such an owner; it is not evidence that current Browser WebSocket sessions dispatch remote asset jobs.

## Cooked font and diagnostic output

`FontGlyphSet.EnsureLayoutResourcesReady` checks the host-file capability only after detecting a missing glyph or atlas resource. A Browser or caller-thread owner gets `Font.CookedLayoutMissing` with the concrete layout issue and font identity. The normal Browser font route is preloaded cooked bitmap data; `LoadEngineFontAsync` is an initial-load API, not a synchronous recovery mechanism for an already-used font instance. Admitted desktop recovery still tries the source font import.

`VPRC_CaptureFrame` checks host output before render readback when a file capture is due, and its writer checks again before creating the directory. HiZ stage logging checks at flush, and crash breadcrumbs check when enabled before building the file path. Disabled or non-capturing render frames do not acquire file-read leases. The public speed-profile start reports `AssetSource.HostFileUnavailable` before creating its output directory. Metadata log-path lookup and file writers also check before host output. `ArchiveExtractor` has no in-repository C# caller, but its public iterator and async entry now reject unsupported host extraction before temp-directory or worker activity; archive parsing itself is unchanged.

The archive extraction implementation now resides in `XREngine.Runtime.Platform.Desktop/ArchiveExtractor.cs`; its progress record and phase enum remain in `XREngine.Data`. This removes the extractor's direct file and worker operations from the shared browser project closure while keeping its `XREngine` namespace, signatures, lazy progress sequence and desktop extraction behavior. Source consumers on desktop must reference the existing desktop platform project; consumers compiled against the old declaring assembly must rebuild. The earlier admission checks below predate this source move. Other guarded desktop operations remain in shared projects, so this move does not close the wider blocking and I/O inventory.

The existing `ClientNetworkingManager` NativeTls branch rejects Browser/caller-thread startup with `Realtime.AsyncTransportRequired` before its synchronous connect wait. Browser session setup calls `StartWebSocketAsync`; the native TLS branch does not silently change transports. `SnapshotAssetReference` remains a classified desktop edit/play route: `Engine.PlayMode.EnterPlayModeAsync` captures/restores `WorldStateSnapshot`; `WorldStateSnapshot` uses `SnapshotBinarySerializer.ResolveAssetReference`, which calls the internal `SnapshotAssetReference.Resolve` fallback. Exit play restores the same snapshot. Browser session startup instead calls `BeginStandalonePlayAsync`. The snapshot fallback was not rewritten.

## Qualification

A fresh source image based on the frozen `capture-material-integration-0023` image, with only these source overlays and the already-present NativeTls guard, built `XREngine.Runtime.Host` Release with zero warnings and errors after the final synchronous-resolution reservation adjustment. A production-method probe passed captured catalog A reading A's bytes after an unrelated global source B with the same path was installed; response construction rejected owner disposal during publication; retiring a pending catalog owner canceled the read and prevented response publication. It also verified async-only source reads without `Exists`, and the unchanged desktop raw-byte/path response. Missing cooked font, public archive extraction, speed-profile start, frame-capture writer, crash breadcrumb writer and HiZ stage flush all rejected before forbidden host output. The probe and final build logs are in the task's ignored validation run under `Build/_AgentValidation/20261001-225000-lit-surface/`.
