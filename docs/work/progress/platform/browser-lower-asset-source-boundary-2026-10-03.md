# Lower-level asset source and host-file admission

`TextFile` raw reads and asset-graph external-reference checks now use a Data-owned `IRuntimeAssetReadSource` contract. Runtime.Core installs its adapter when `DirectStorageIO.Source` changes. Both getters observe the same installation, so an unsuccessful replacement cannot leave the Core source and lower-level adapter pointing to different owners. The adapter captures the source; catalog existence checks use catalog identities instead of host paths. An unrelated asset manager binding or unbinding does not retire these global raw-read operations.

A synchronous raw read requires a source that explicitly supports synchronous bytes. Caller-thread and browser execution additionally reject a source's host-file probes and synchronous host-file reads. Asynchronous text reads await the captured source directly; a caller-thread host-file source skips the synchronous existence probe. Standalone desktop text loading retains its existing no-source file fallback. A browser or caller-thread runtime without a source cannot enter that fallback. These APIs read raw text; cooked objects continue to use the existing asset manager deserialization and ownership path.

Each installed source has a distinct lifetime, including replacement followed by reinstating the same source object. Replacement or uninstall invalidates pending reads and cancels their linked tokens outside the installation gate. A read retains its original source and lifetime until completion; it cannot retarget a replacement. Cancellation state is disposed only after retirement callbacks and the last reader finish. Source replacement reserves its new state before retiring the previous state.

Text decoding finishes before publication. Publication briefly reserves both the captured source and the destination text object's current request. Source replacement and destruction or another load of that object reject reentrant publication overlap with a named `PublicationInProgress` error; they can be retried after the setter callbacks return. User-notifying setters, source methods, cancellation callbacks, and decoding execute outside the new admission gates. A destroyed or revived destination and a superseded request cannot accept an earlier pending read. Lazy encoding lookup also captures the request version and path before reading; its cache update checks the source, owner, path, and newer text publication. It retains the historical nonnotifying scalar assignment. Cancellation before publication discards the read. Already admitted synchronous setter callbacks retain normal property notification semantics, including callback exceptions; this is not a transactional rollback of user callbacks.

Context-aware and options-aware `TextFile` async imports use the same asynchronous read path. The context cancellation token is preserved. Default `XRAsset` async import and reload wrappers require host-file/background admission before scheduling their existing desktop operation, recheck when it starts, and retain the source reservation through that synchronous operation. They do not turn host-only importers into runtime decoders. Asset serialization, text saves, and asset memory mapping reject unavailable host capability before touching files. Existing desktop authoring behavior remains available.

Both legacy mapping APIs, `XREngine.FileMap` and `System.FileMap`, capture `IFileMappingBackend` before probing, opening, or creating any file or temporary file. Their public stream routes demand both host-file admission and the mapping capability before querying stream length, including when a desktop backend remains installed during caller execution. Borrowed-stream and owned-stream disposal behavior remains unchanged. `XRAsset.OpenForStreaming` retains its existing direct .NET mapping implementation on an admitted desktop host without demanding the unrelated mapping backend. The text BOM decoder uses bounded spans, including empty or shorter-than-four-byte inputs and both UTF-32 byte orders. Text serialization members and storage shape are unchanged.

The caller-thread policy bridge is enabled before extensible caller configuration hooks, rolls back on configuration failure, and is cleared after successful shutdown. Reentrant shutdown during caller configuration returns the existing not-stopped result instead of clearing admission underneath the hook. Desktop configuration behavior and worker topology are unchanged.

## Local validation

An ignored production-method probe first passed 15 checks against the pre-overlay isolated source tree: desktop text reads and saves, text serialized roundtrip, default import/context/options/reload, serialization, and existing synchronous/asynchronous catalog byte routes. The final source is compiled as a bounded overlay on the stable runtime tree, in its own artifacts directory under the shared build lock. No tracked tests were added or changed.

The final isolated Data/Core and probe build reports zero warnings and errors, and the extended probe passes 136 checks. It covers source and catalog reads, caller-thread admission including failed/reentrant configuration hooks, replacement/uninstall/ABA retirement, cancellation (including reentrant and throwing cancellation callbacks), destination destruction/revival, superseded requests, borrowed external references, reentrant publication without an installation lock, both mapping APIs, owned and borrowed stream cleanup, failed mapped assignment cleanup, and bounded BOM decoding. It deserializes bytes emitted by the old implementation and verifies byte-identical reserialization. Independent review reproduced the retained-backend stream admission gap, an unintended standalone mapping restriction, and a lazy-encoding race that overwrote a newer text load's encoding; all three are included in the corrected source and extended probe. This is managed production-method evidence, not browser playback or a native mapping backend qualification.

## Remaining explicit boundaries

This change does not close every file operation in the shared runtime. Direct synchronous `XRScene.Load3rdParty`, project descriptor load/create/save, and `XRMesh.Reload` still need their own admission or source-read treatment. The mesh and texture YAML external-reference resolvers still contain host existence checks after their cache-hit paths. The Gaussian and DDGI path loaders and renderer-module assembly hashing also remain separate reachability/ownership reviews. `MeshletPayloadDiskCache` has no call sites in the bounded Rendering C# inventory reviewed here; no runtime reachability claim or change is made for that helper.
