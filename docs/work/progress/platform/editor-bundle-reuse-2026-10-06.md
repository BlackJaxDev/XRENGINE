# Windows Editor bundle reuse in browser CI

The portable browser workflow can reuse nine Editor browser bundles for a narrow browser-harness change. The Windows job selects a prior completed run of the same workflow. It does this only on the first push attempt from the public `BlackJaxDev/XRENGINE` repository to `codex/webgpu-readiness-audit`. A pull request, manual run, fork, rerun, or `master` push takes the full Windows path.

The selector uses the exact checked-out commit. It checks that the prior source commit is an ancestor. It reads the full local Git raw diff as NUL-separated bytes. It allows regular `100644` modifications only to `advanced-shadow-parity-game.mjs`, `shadow-image-math.mjs`, `shadow-image-worker.mjs`, and Markdown files below `docs/work/`. A changed workflow, helper, engine, sample, fixture, publisher, or network source forces a full build. The first commit that adds this selector changes the workflow and therefore forces a full build.

The prior run must be a completed first push attempt from the same repository, workflow, and branch. Its single successful Windows job must show real publisher, verification, receipt, and nine bundle-upload steps as successful. Other jobs in that run can fail. A job that reused bundles cannot be a producer. The selector requires one unique, unexpired artifact for each of the nine bundle names. It checks each artifact's ID, source run and commit, creation and finalization time within the producer job, SHA-256 digest, and bounded nonzero size.

Before the Windows build is skipped, the selector downloads all nine original ZIP archives. It checks each ZIP's exact size and SHA-256 before opening it. It uses .NET `ZipArchive` to reject unsafe paths, unsupported file types, duplicate or ambiguous names, oversized entries, and expansion beyond the size or time limits. The limits are 256 MiB per ZIP, 512 MiB expanded per bundle, 128 MiB per entry, and 10,000 entries. The selector has a five-minute budget and a seven-minute step timeout. Git and HTTP reads use cancellation, but a single OS or ZIP read might not stop at once; the outer step timeout is the final bound. Larger or slower inputs use the full Windows path. The selector removes its own temporary archive and extraction files after each check. It then requires the expected publication files and shadow receipt. Extraction uses fresh roots on a hosted runner and checks existing ancestors for reparse points. This is not a general guarantee against another process changing the file system at the same time. The reused path saves a provenance record with the current harness commit, producer run, attempt, job, source commit, artifact IDs, digests, sizes, and checks. It never republishes the old bundles as current artifacts.

Linux Chromium qualification keeps the same matrix and commands. Each reused game job downloads its exact original artifact ID again and validates the archive before extraction. The two comparison jobs also validate their exact CPU or shadow-OFF reference artifact. A failed later download stops that game job before bundle execution. The static workflow graph cannot start a Windows rebuild after that failure. A failed-jobs-only rerun can keep successful Windows outputs from attempt one. The downloader rejects that stale attempt before game execution. A full workflow rerun is required in that case.

The optional native networking bundle is separate from these nine artifacts. Reuse does not build or upload it. The held networking walkthrough remains unchanged.

Any missing source history, GitHub proof, artifact metadata, archive bytes, or safe extraction forces the full Windows path. A selector error after it writes `reuse=true` also forces the full path because the workflow checks the selector step outcome. Full-path steps keep the normal success condition. Evidence uploads that normally run on failure retain their `always()` condition on the full path.

The code has local PowerShell syntax and bounded scratch-case checks. A hosted Windows run and a reused Linux run still need observation after review and publication.
