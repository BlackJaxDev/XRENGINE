# Gaussian and baked DDGI asset consumers

In caller-thread mode, `GaussianSplatComponent` and `DDGIFrameContext` read their existing `.splat` and `.ddgi` formats through one captured asynchronous asset-source lease per request. Decoding uses the existing stream parsers. The component or pipeline adopts a result only through its captured render-job manager after checking request, path, authored revision, source installation, and owner lifetime. A queued job is observed through its `JobHandle`; cancellation releases the read and decoded payload even if the owner job is never pumped. Desktop paths retain their synchronous loaders.

A pending replacement keeps the previous valid cloud or baked asset. Explicit `Cloud`, `Model`, and `BakedAsset` assignments win over an older read. Gaussian-generated model, submesh, and mesh assets have exact component ownership; shared or externally supplied materials and assets remain borrowed. Failed retirement remains recorded for a later retry. Pipeline cache clear, component teardown, volume deactivation, and source replacement invalidate pending work. DDGI path changes retain prior baked content only in caller mode; the ordinary desktop path still clears it for synchronous reload.
