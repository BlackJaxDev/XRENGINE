# Runtime asset wrapper admission

The remaining bounded scene, project, serialization-reference, mesh-reload, Gaussian, DDGI, and renderer-module path wrappers now classify their source before host file operations. Third-party scene import and project descriptor import, project creation/structure/save, mesh reload, DDGI path save, and assembly hashing require host-file admission before probing or writing. Mesh reload retains its original host-file byte path and attachment lifecycle. Its asynchronous inherited wrapper already rejects caller-thread host work before scheduling.

Project descriptor loads use their serialization owner to decide object identity and cache behavior. The serialization contract exposes whether that owner admits host project directories; its AssetManager implementation uses the owner's synchronous-work admission and its Runtime decorator forwards the capability. Successful admitted desktop loads still create the standard directories. Catalog or caller loads keep the descriptor's virtual path without creating directories. The third-party descriptor import remains a direct admitted host YAML route. Explicit `EnsureStructure` remains an authoring operation.

Texture and mesh YAML external references retain cached identity first. The serialization owner's ID-to-path resolver already validates host or catalog identity, so the converters no longer perform a second, unrelated host existence check. They defer through that same serialization owner before invoking its immediate load. Published YAML restrictions and envelope formats are unchanged.

Gaussian and DDGI path loaders use a captured raw-read source. Their Stream decoders are unchanged and still work for in-memory inputs. The Gaussian result retains its filename-derived name; the DDGI path result preserves the same bytes and missing-file exception. Their synchronous path entry points diagnose a source requiring asynchronous bytes. The subsequent [caller-consumer integration](browser-gaussian-ddgi-asset-consumers-2026-10-04.md) connects `GaussianSplatComponent` and `DDGIFrameContext` to asynchronous reads with owner-side adoption and cancellation. `RendererBackendModuleIdentity.GetBuildHash` reads an assembly image from an admitted host path; an assembly without a location retains its empty-hash result.

`MeshletPayloadDiskCache` has no ordinary tracked C# caller in the Rendering inventory, so it remains a host disk-cache helper without a claimed browser runtime route. The remaining unadmitted project root enumeration goes through the installed `AssetFileSystemServices` host-discovery capability and has no tracked caller; it is not an ordinary browser path.

The isolated source uses the stable runtime tree with only the reviewed lower raw-I/O source packet and this wrapper patch overlaid. Its final owner-aware build passed with zero warnings/errors and its production-method probe passed 24 checks. These cover desktop project structure, DDGI and Gaussian file routes; catalog-like virtual bytes and identity; owner/catalog independence from an unrelated raw source; host capability rejection before path side effects; and async-only path diagnostics. No tracked tests, dependencies, serialized formats, desktop topology, or release files changed. No browser playback claim is made.

## Asynchronous byte loaders

`GaussianSplatCloud.LoadAsync` and `DDGIBakedAsset.LoadAsync` capture the installed raw source and cancellation epoch before reading bytes. They use the existing Stream decoders and preserve the Gaussian missing-file result, DDGI missing-file exception and filename-derived cloud name. They do not schedule a blocking worker job. A source publication reservation covers decoding and return; cancellation or source retirement rejects stale bytes. Failed Gaussian publication releases the newly constructed object while preserving the original exception. The synchronous desktop APIs remain available.

The isolated loader build passed with zero warnings/errors. Twenty-one production-method checks cover delayed async-only reads without synchronous source calls, source replacement, cancellation before and during a read, missing and malformed inputs, skipped host existence probes in caller mode, and both ordinary asynchronous and synchronous desktop routes. These are loader checks. The subsequent consumer implementation passes its isolated Rendering build, independent ownership review and 40 focused runtime checks; rendered browser Gaussian and DDGI output remains separate acceptance.

The final isolated Rendering/Core/Data/probe build completed with zero warnings and errors. The final probe passed 24 checks, including an independent serialization owner bound to a catalog identity while an unrelated raw source was installed. The build and probe logs are in that run's `logs/` directory.

`MeshletPayloadDiskCache.cs` was physically moved from Rendering into `XREngine.Runtime.MeshProcessing.Meshoptimizer/Rendering/`; its cache format and serialization calls are unchanged.
