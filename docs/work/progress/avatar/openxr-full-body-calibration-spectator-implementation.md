# OpenXR full-body calibration and spectator implementation record

This record describes the current implementation and validation evidence. The [body tracking guide](../../../developer-guides/vr/openxr-body-tracking.md) defines the intended behavior. Open checks are in [Avatar Validation](../../testing/avatar/avatar-validation.md), and open code items are in the [VR full-body estimation todo](../../todo/avatar/vr-full-body-estimation-todo.md#calibration-and-spectator-follow-ups).

Root causes, rejected hypotheses, and the live solver measurements are recorded in the [integration investigation](../../investigations/avatar/vr-full-body-calibration-2026-09-26.md).

## Implemented behavior under review

- OpenXR tracker pose actions use enumerated persistent paths as subactions. Suggested VIVE tracker profile bindings use the extension's role paths only. Scene trackers are keyed by persistent identity, so metadata changes do not create another tracker node. OpenVR tracker identity uses the physical serial number rather than the device index.
- Current tracker pose availability is cleared when the pose action is inactive or the space lacks valid position or orientation. Headset lookup rejects the rendering fallback used on tracking loss, and controller and tracker samples share a predicted snapshot identifier. Raw device transforms retain their last transform for rendering when a real pose becomes unavailable; capture queries reject that retained value.
- A throttled provider enumeration records tracker presence without inferring why an absent tracker disappeared. Tracker diagnostics distinguish provider unavailable, undiscovered, absent, unbound, inactive, lost tracking, stale sample, and usable pose. Per-call value snapshots of the tracker metadata are copied under the same pose-cache lock as the current sample. Real OpenXR samples also expire after 250 ms or when the session stops, even if the frame identifier has not advanced. The last valid pose remains a diagnostic and is never supplied as a current capture pose.
- Periodic tracker enumeration now runs after frame submission rather than inside predicted pose publication. An explicit calibration refresh recreates the session only while a currently reported tracker lacks an action space; a tracker that disappeared before the request no longer forces a restart.
- Pose acceptance also rejects non-finite positions, degenerate orientation samples, and non-finite composed world matrices. A tracker absent from the latest provider enumeration cannot be returned as a current tracker pose, even if an action-space cache still contains data for that path.
- Avatar eye height, eye-to-head offset, and arm span are measured from bind geometry in humanoid-root coordinates. This keeps the measurement denominator independent of avatar root motion, applied scale, and animated bones. Scale waits for a measured avatar eye height, and entering a valid standing height clears the missing-measurement notice. Explicit optional middle fingertip endpoint mappings supply wrist-to-tip distances; each missing endpoint uses an estimated hand length with a notice. Middle distal joints are never passed off as fingertips.
- A tracker connected after action creation requests a controlled input refresh when calibration opens. The render owner waits for a drained frame before recreating the OpenXR session. This may briefly interrupt the headset view; the player must reopen calibration afterward.
- OpenXR calibration commands are distinct from mute and arrive on press edges regardless of desktop camera possession. The player owns capture, cancellation, tracker assignment, target offsets, and session restoration. A separate spectator camera and desktop output selector leave OpenXR eye camera ownership unchanged.
- Session calibration is cached against the avatar node's runtime object identity and checked against its prefab and bind-pose signature. Reparenting that node into a temporary editor VR pawn preserves its calibration; replacing it with another instance, even from the same prefab, requires a new capture. The cache holds avatar keys weakly and remains in memory only.
- Synthetic poses require an explicit debug flag and identity. Invalid synthetic poses cannot become calibration samples, and a failed real pose lookup never enables the debug path.

## Validation evidence and open gates

The isolated editor build succeeded with zero warnings and zero errors. Validation uses the named `vr-fullbody` MCP editor, explicit synthetic tracking, an imported humanoid, OpenGL, and a disposable copy of unit-world settings. Evidence is under `Build/_AgentValidation/20260926-190000-vr-fullbody/`; the evidence is disposable and the findings below are the durable record.

- Live calibration committed with the headset, controllers, and all eight synthetic trackers. Each body tracker was mounted with a nonidentity rotation. The preview assigned all eight to distinct expected slots, and capture returned `Calibrated` with `HasCalibration=true`.
- An invalid controller pose rejected capture with a tracking message and retained the previous calibration. A tilted headset rejected capture with the head-level message and retained it. Cancel returned to `Calibrated` without recapturing.
- Invalidating the bound hips tracker reduced its source weight to zero while every other slot remained at one. Reenabling that same identity restored its weight to one.
- The live run exposed eye-offset measurement contamination by avatar world translation. Measuring bind geometry in avatar-root coordinates corrected the vertical eye offset from 1.282979 m to 0.038671494 m for this imported avatar. The scaled eye offset became 0.051738456 m for a 1.75 m standing-height entry; the missing-measurement notice cleared.
- The imported avatar's left side is positive local X. Hardcoded negative-X arm alignment crossed its arms during calibration. Canonical arm directions now derive from the avatar's bind shoulders. A subsequent live run confirmed a separated canonical stance under the rotated player root.
- A later spectator view exposed a separate facing mismatch: this avatar's bind-body forward is local positive Z while the headset's forward convention is negative Z. Canonical root yaw now includes the humanoid's bind-body basis correction. Head and wrist targets include fixed bind-bone orientation in that corrected basis; the measured eye displacement is converted into the same basis. Spectator follow uses the humanoid's semantic forward instead of assuming a bone axis. Live validation confirmed stationary root heading, matching head and wrist rotations, and a spectator image from behind the avatar.
- Screenshots were captured and viewed from the centered spectator position and with a 1.2 m shoulder offset. The camera follows behind the avatar, with its own world transform. An unpossessed scene camera is not sufficient for viewport validation: the screenshot helper can fall back to the active editor viewport. The synthetic pawn was explicitly possessed before capturing the spectator views.
- Advanced-pipeline screenshots were severely overexposed; the default pipeline gave usable pose evidence. Advanced offscreen capture encountered a bindless sampling-state transition failure, so the spectator explicitly uses the existing Default GPU offscreen path and raw linear HDR contract. Completed images were initially zero until imported skinned bounds were established. A bounded unculled warm-up now establishes those bounds, then restores frustum culling. Live validation confirmed both capture slots returned to culling, completion serials advanced, and the completed 1920 × 1080 texture contained the avatar and environment. The final HDR scene-capture policy removed debug labels, capsule, and axes from the texture; its captured RGB maximum was 1.9570 and mean 0.5783, with no nonfinite samples. The background alpha remains mostly zero (mean 0.0435), so consumers that need opaque video must force opaque alpha after capture. Completion counters alone were not accepted as image evidence.
- Final desktop spectator screenshots at 3 m and 5 m both showed the avatar from behind after culling resumed. The desktop and offscreen images both show straight bright arms above bent darker arms. The imported hierarchy contains one avatar root but multiple active body model nodes (`Body`, `Body.002`, and `Milltina_body`); further FBX inspection identified meshes bound to independent Yuno and Lumi skeletons alongside the selected humanoid skeleton. Isolating those foreign-rig meshes still left one bright straight arm: disabling the same-rig `Shirt` mesh removed it. A 0.0254 bind-scale lead remains for skinning investigation. All 72 mesh nodes lack authored visibility overrides, ruling out lost importer visibility. Validation selects the matching rig meshes explicitly; production import does not guess which variants to hide. Physical-headset spectator framing and performance acceptance remain open.
- The pelvis defect persisted after storing the canonical pose as the solver reset baseline. Isolating optional sources ruled out the chest, upper arms, knees, and feet as its cause. The trigonometric solver used a negative axial component despite its look-rotation helper mapping positive Z toward the target, and used adjacent-bone lengths even when solving across skipped joints. The direct geometric correction restored head, hips, and feet to their targets. Eight steady hips samples matched within approximately one micrometer. A 10 cm foot translation produced the corresponding 10 cm solved movement, and a 20-degree chest rotation produced approximately 18.3 degrees of chest rotation.
- Final live captures with zero, three, and eight optional trackers succeeded as 3-, 6-, and 11-point configurations. All eleven target identities stayed unchanged across captures. With reachable controller positions, raising an upper-arm tracker 12 cm raised the elbow 4.85 cm; a knee goal translated in world X/Z by −6.92/−7.22 cm moved the knee in the same direction by −4.15/−4.92 cm. Hand and foot constraints remain authoritative when limb goals conflict. Controller and tracker poses were restored after these checks.
- Same-process calibration restoration retained all eleven targets while a bound knee tracker was invalid. Its weight remained zero until the same identity became valid, then recovered to one. This validates restoration and missing-source handling, but does not substitute for the physical editor VR toggle acceptance.
- Snapshot checks now include sample time as well as frame identity. Tracker assignment consumes one cached coherent publication; capture and session restoration reject a mixed publication. Optional estimates are sampled before room-scale movement and rebased alongside tracked poses. Losing a bound hips source suspends room-scale recentering instead of switching locomotion to head lean.
- Moving the synthetic headset and hips 15 cm together under the arbitrary mount offset produced an exact 15 cm playspace adjustment, without a doubled offset or drift in the aligned targets and bones. Restoring those poses restored the playspace. This edit-mode check established target-space recentering only; the later Play-mode check below resolved its locomotion question.
- The validation cleanup helper now preserves timestamp precision when PowerShell has deserialized a session timestamp as a date object. The old string conversion lost fractional seconds and could misclassify an active isolated session as inactive. The corrected ownership check protected the live session during cleanup.

The corrected solver, spectator warm-up, and clean offscreen policy have passed the synthetic live checks above. One physical SteamVR editor avatar borrow/restore cycle preserved the avatar identity, original parent, and original animation and IK writer states; the temporary VR owners were removed on toggle-off. Focused regression results and lease details are recorded in the [integration investigation](../../investigations/avatar/vr-full-body-calibration-2026-09-26.md). Repeated toggle durability and other hardware release gates remain open.

The former explicit persistence regression now runs normally and verifies eleven stable avatar-owned targets. The focused calibration, exhaustive assignment, and mutable input callback selection passed 16/16 with no skips; the later expanded focused selection passed 19/19. Tests cover every permutation of eight body trackers with two distant extras, three/six/eleven-point recaptures, rollback, missing-identity restoration, head tilt refusal with yaw acceptance, arbitrary mount rotations, and avatar scale under a rotated playspace. A fresh-parent inverse bug exposed by the scale test was corrected by recalculating dirty ancestors before world-to-local target conversion.

The broader animation, input, and VR rendering selection initially passed 221/283, with 62 failures; after a related OpenXR source-contract correction it passed 224/285, with 61 failures. Representative humanoid-preset and rendering source-contract failures also reproduce in isolation. The neutral-preset failure expects a global bone table although the committed implementation deliberately returns no embedded overrides; source-contract failures include superseded call shapes. These observations do not establish a clean baseline for every broader failure. Results are retained in `reports/vr-core-tests-final.trx`, `reports/vr-broad-tests.trx`, and `reports/vr-broad-tests-final.trx` under the evidence run.
Physical OpenXR startup and eye submission were exercised, but full controller/tracker calibration acceptance has not passed. Role-free streaming through SteamVR's OpenXR runtime, multiple identical tracker metadata paths, late connection, reconnection, disabled tracker behavior, every supported controller binding, headset timing, and spectator cost remain hardware gates. Controller wrist presets are engine-authored anatomical starting values in normalized grip space, not measured vendor alignments. Native HTCX enumeration returned zero paths in two probes; advertising the extension does not prove that SteamVR exposes tracker poses through it. This limitation must be recorded rather than hidden behind an automatic provider switch.

The OpenVR.NET device facade exposes a current pose matrix and tracking state but no pose publication timestamp or frame identifier. OpenVR capture checks enabled and running tracking state, but cannot prove sample age if that provider's update loop stalls. An unchanged matrix is not treated as stale because a stationary device may legitimately retain the same pose.

The final session log also recorded one `AxisManager.ExecuteList` collection-modification exception during the MCP-driven pawn possession change. The editor continued and subsequent live checks ran. This occurs in the existing gamepad callback list and is outside the calibration source changes; the callback storage has since been corrected and covered by mutation-during-dispatch tests. Those earlier logs are not claimed to be exception-free.
## Continued runtime validation

A subsequent Play-mode run with a static physics floor completed room-scale locomotion. Moving the bound hips and headset by 15 cm moved the player root by the same displacement in the rotated playspace. Restoring both poses returned the root within 0.5 micrometers in X; the playspace local offset returned from -15 cm to zero. The earlier edit-mode observation did not establish a locomotion defect. A separate supported-character state defect left MovementMode reporting Falling after landing. Support reconciliation now updates Walking/Falling while preserving Flying/Swimming; the deterministic support-transition regression passes, and the rebuilt live character reports Walking with an upward ground normal.

The input callback mutation exception is corrected with registration-time copy-on-write callback arrays; dispatch reads a stable snapshot without per-frame collection allocation. Focused tests cover subscription mutation during axis and button dispatch.

An initial SteamVR 2.17.10 inventory reported a Beyond headset and one Tundra tracker, with no connected controllers; a later OpenVR inventory named three Tundra trackers with valid poses plus a pair of Knuckles controllers. Native OpenXR instance/system and required-extension probes pass. The real graphics session exposed repeated creation/teardown before session start. Deferred OpenGL session construction now excludes event polling until swapchains and input are ready. The rebuilt session reached Focused, retained lifecycle epoch 1 without teardown, and submitted hundreds of frames to both eyes with no runtime failure. The native HTCX path probe returned zero paths twice even with the later OpenVR tracker inventory; no OpenXR tracker pose was established. The SteamVR smoke preflight also exposed an incorrect 32-bit native XrVersion field; using its required 64-bit layout and checking the native structure size eliminated the observed heap corruption.
The source allocation audit reported 72 formatted-logging candidates. It scans all matching OpenXR files, including initialization, state transitions, diagnostic-gated output, and errors; this result is a failed static candidate gate, not a measured steady-state allocation count. The report is retained under `reports/allocation-audit.md` in the evidence run.

The rebuilt synthetic session passed a frozen-camera culling comparison: both culling enabled and disabled showed the avatar, with 110 opaque mesh commands in each view. Global broad-phase rejection diagnostics did not identify the active spectator view and were not treated as evidence for another renderer change. All eleven calibration targets were populated and the grounded character reported Walking. The temporary height was restored and that named session was stopped.

The earlier focused calibration, movement, callback, and OpenXR binding selection passed 19/19. An intermediate targeted selection passed 21/22 because removing a later callback suppressed it in the current dispatch. The callback dispatch fix and avatar-instance cache fix were covered by the subsequent focused 24/24 result, including a stable root-node snapshot regression. Its broader selection passed 229/290; its 61 failure names exactly matched the prior 224/285 selection. Corrected suggested paths use Vive squeeze click, Touch trigger value, and Windows Mixed Reality squeeze click/trigger value. The runtime supports conversion between boolean actions and scalar components, so unsupported synthetic click paths are unnecessary.

Real-headset performance samples with one owned validation editor running recorded a first-person desktop render median of 40.0012 ms (95th percentile 317.3575 ms) and a spectator median of 56.0683 ms (95th percentile 76.3531 ms). All 25 and 75 submitted headset frames respectively missed their deadlines. Whole-process managed allocation rates were approximately 30.0 MB/s and 90.6 MB/s, including all editor threads and MCP sampling. These short Debug samples include the multi-rig asset, diagnostic overlays, and concurrent external GPU activity; they fail timing acceptance and do not isolate the spectator's own allocation cost. The MCP OpenGL eye-pipeline readback guard was corrected so OpenGL can attempt direct readback while Vulkan still requires its planner scope. A right-eye `HDRSceneTex` capture from the earlier Focused session showed finite sky and horizon; a left-eye `FinalPostProcessOutputTexture` capture was black. These are internal pipeline resources, not the final eye image: OpenGL renders each eye into `OpenXRViewportMirrorColor` before blitting to the runtime swapchain. Both preview FBOs had incomplete attachments because their GL textures lacked committed storage. The preview allocation path now commits immutable storage before the attachment and only copies when the existing preview setting is enabled. That checkpoint's rebuild succeeded with zero warnings and errors, but its physical session remained Ready with zero submitted frames; the left-eye preview request timed out after 20 seconds. Thus the preview fix and final headset image remain unvalidated in runtime. Reports include `hardware-final-diagnostics.json` and `hardware-final-left-preview.json`. Vulkan had not yet been run at that checkpoint.

The Ready/zero-frame session recorded a `Collection was modified` exception while `XRViewport.ResolveScreenSpaceUICanvas` enumerated the world root list during an editor pawn switch. A deterministic retained-snapshot regression passes, and the consolidated editor build completed with zero warnings and errors. This fixes the proven exception path, but a new headset eye frame and root-switch run have not yet confirmed it live.
