# Full-body VR calibration

OpenXR uses the headset, both controllers, and up to eight additional trackers to place a local avatar. The tracker slots are hips, chest, left and right foot, left and right upper arm, and left and right knee. You can calibrate with fewer trackers; an empty slot does not gain a tracker target. Tracker placement is chosen by proximity when you capture, then stays fixed until you calibrate again. Controller grips use preset wrist offsets, so you can hold the controllers naturally.

Before capture, set **BodyMeasurementMode** and the matching **PlayerHeight** or **PlayerArmSpan** value in the player's **VR Body** settings. Height means standing height in meters; the engine estimates eye height as 93.6% of that value. Arm span means fingertip-to-fingertip distance in meters. An avatar can map optional **LeftMiddleFingertipNode** and **RightMiddleFingertipNode** endpoints for that measurement. Each missing endpoint uses an estimated hand length and shows a notice; a middle distal joint is not treated as a fingertip. Zero means unset and prevents full-body capture. Avatar scale also waits for a measured avatar eye height; a missing bone mapping cannot silently use a default model height. Moving the headset does not change scale. You can enter the measurement in the settings UI or while calibrating: hold the calibration-open button for about a second to enter measurement editing, use left or right trigger to change the value by 1 cm, press both triggers to switch between height and arm span, then hold the calibration-open button again to finish. Capture is suppressed while editing; cancel remains available.

Open calibration with the left controller's calibration button. The current OpenXR suggestions use left A on Index, left Y on Touch, and left menu on Vive, Windows Mixed Reality, and simple controllers. Cancel uses right B on Index and Touch, or right menu on Vive, Windows Mixed Reality, and simple controllers. The active runtime may supply a different binding. Calibration input remains available while the desktop editor camera is selected.

The avatar holds a T-pose aligned to the headset. Stand straight with your feet in the footprints, match your upper arms to the avatar when wearing those trackers, and look ahead with your head level. Markers show each tracker's proposed slot or that it is unassigned. Pull both triggers together to capture; simple controllers use both select buttons. Capture checks current headset and controller tracking, head tilt, and a brief stationary window. It commits immediately when valid. A failure explains the reason and restores the previous calibrated rig. Cancel also restores the previous rig. Repeat calibration whenever trackers are moved or swapped.

A disconnected tracker stops contributing its slot. The same physical tracker can resume its previous slot after reconnection in the same session; another tracker cannot inherit it until capture. A late-connected OpenXR tracker may trigger a controlled OpenXR session refresh when calibration opens. If the headset view briefly restarts, reopen calibration after tracking returns. A tracking-origin or reference-space change asks for recalibration.

Tracker assignment uses proximity and each device's identity within the session. OpenXR pose transport requires `XR_HTCX_vive_tracker_interaction` and a valid persistent-path action pose. Some SteamVR runtime configurations may enumerate a tracker without streaming that pose; this has not yet been verified on named hardware. An unavailable tracker is shown as unavailable, without an automatic OpenVR pose fallback.

Tracker diagnostics distinguish missing discovery, unavailable provider, unbound action, inactive action, stale sample, and lost tracking. When SteamVR omits a previously discovered tracker, OpenXR does not reveal whether it was disabled or disconnected; the status reports **DisabledOrNotReported** instead of guessing.

The editor's VR view selector offers **First Person**, **Spectator**, **Editor Camera**, and **Spectator Texture**. The first three select the desktop pawn's camera; Spectator Texture keeps a first-person desktop preview while publishing a completed offscreen spectator image for capture consumers. The spectator scene renders through only one output mode at a time. Switching views does not change headset eye cameras, controller input, possession, tracking origin, or the headset audio listener.

The spectator has its own monoscopic camera. It follows the player's floor position and semantic body heading from the hips source, with the avatar's body heading as fallback. A collision boom moves the camera closer when static geometry obstructs it. **VR Spectator** user settings control its enabled default, distance, height, shoulder offset, aim height, field of view, and follow speed. Texture output also uses **VrSpectatorWidth**, **VrSpectatorHeightPixels**, and **VrSpectatorFramesPerSecond**; defaults are 1920 × 1080 at 30 frames per second. These values are read when the rig is created. The desktop viewport uses its normal presentation size, cadence, and post-processing. The offscreen texture is linear HDR color without post-processing or temporal history; capture consumers must handle color conversion and force opaque alpha when needed for their display or encoder. Each spectator view starts with a short unculled warm-up to establish imported skinned bounds, then resumes frustum culling. A camera cut or offscreen target rebuild repeats that warm-up.

The local avatar's complete mesh is visible to the spectator and editor cameras. While the VR rig is active, the engine assigns its imported mesh renderers to the reserved **Local VR Avatar** layer (index 30); headset eyes and the first-person desktop camera exclude that layer. This hides the local avatar from those close cameras without deactivating the mesh for other views. Abrupt tracking-origin changes and view switches reset spectator follow smoothing and desktop-view temporal history; texture output withholds frames from before the change until a fresh capture completes.

For an imported file containing multiple independent skeletons or clothing variants, select the renderers belonging to the calibrated humanoid. Meshes bound to another skeleton retain that skeleton's pose; the engine does not automatically hide or retarget them. Disable unwanted variants in the scene while retaining the intended accessories.

When the editor creates a temporary VR character pawn in a desktop world, it can borrow one imported avatar from that world. It pauses the avatar's desktop scaling, IK, and animation writers, mounts the avatar under the VR character, and binds the shared calibration rig. Turning VR off returns the same avatar to its original parent and transform and restores those desktop writers. Committed calibration can be restored only while the same provider session and reference space remain valid; a restarted OpenXR session can require recalibration. If several avatars are eligible, select a desktop pawn whose hierarchy contains the intended avatar; an ambiguous scene is left unchanged and the editor shows a diagnostic. Full-body binding requires a character pawn with locomotion enabled.
